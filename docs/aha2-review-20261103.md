# AHA2 源码审查与 Duo 采用计划

审查日期：2026-11-03。AHA2 基准为公开仓库提交 [`3698996a57e03469bf278f417eda62aa37184e0a`](https://github.com/ChinaKai/AHA2/commit/3698996a57e03469bf278f417eda62aa37184e0a)（2026-11-02）；Duo 对照基准为 v0.34.69 `ee6dedef`，本轮实现进入 v0.34.70。

相对此前本地 AHA2 审查副本 `d480bd8e`，本次基准新增 107 个提交；重点新增方向包括窄渠道 MCP、多后端注册、群任务权限与回复路由、自动助手任务关注和模型环境修复。

## 结论与本轮交付

AHA2 最值得借鉴的是：按需读取有版本的知识、独立候选与审阅、后端共用的 MCP 注册、任务／轮次凭证、与入站消息绑定的渠道回复，以及当前上下文和累计计费用量分离。Duo 已有任务 Markdown、三类知识、修订基线、范围检索、硬件租约和桌面代次校验，可沿现有实现补齐，不需要另建一套知识根或迁成 AHA2 数据库模型。

本轮落地三个可独立验证的改进：

1. **便签置顶与单条配色**：每条保存 `pinned`、`color`；置顶优先、同组原顺序；保留输入节点、草稿与并发保护。旧便签继承原颜色，新便签默认色，导入不改变其他便签。
2. **正式知识空白与重复检查**：在“知识库 → 目录与整理”显式触发，只读列出标题／注释大纲和同分类、同范围的同正文候选，可打开原笔记修订。没有删除、语义合并、模型调用或用户目录清理。
3. **Codex 当前上下文占用**：使用原生最新请求输入及真实模型窗口，压缩后可下降；累计计费链路保持独立。无有效窗口时不猜容量。

## 1. 知识：借鉴流程，保留 Markdown 原件与证据语义

### 数据流与渐进读取

AHA2 的知识主数据在数据库，任务上下文 Markdown 是生成快照。`internal/prompt/registry.go:755,808,1221,1283,1419` 构建共享内容哈希、索引和详情资源；`internal/workspace/context.go:20,47` 将快照限制在当前任务根。常驻提示词可以只给入口，再按需读取详情。

`internal/store/knowledge_libraries.go:86,96,449` 区分外部只读库与可贡献修订的项目绑定；`internal/store/channel_knowledge.go:61` 进一步限制渠道的知识子树授权。对 Duo 的启发是：检索范围、知识正文身份与工具访问权限分别表达。

Duo 现有 `knowledge_recall.go` 已有项目范围和有界注入，`workspace_worklog_context.go` 已有主文档变化交接。后续可补只读知识工具按需读取正文和来源，以及常驻提示词预算测试；不把所有历史重复塞进提示词。

### 候选、审阅和修订

AHA2 `internal/store/knowledge_proposals.go:227,363,454` 保存完整拟议版本、原始基线与决定，采纳时检查 revision；`internal/httpapi/knowledge_review_handlers.go:46` 批量审阅逐条返回成功／失败。`internal/store/knowledge.go:830` 接受 helped／stale／wrong 反馈，为修订提供明确入口。

Duo 的 `knowledge_revision.go` 与 `knowledge_consolidation.go` 已具备基线检查和待审合并稿。后续适合增加“引用后反馈 → 待修订队列”，先把问题和证据送到对应主题，再由用户或明确授权的整理流程处理。

**采纳和验证应分开。** AHA2 `knowledge_proposals.go:378` 采纳后直接置 `verified`，`app/service.go:1878` 自动批准也走此路径；普通提案创建时还会把旧条目置 stale（`:311`）。Duo 应保留 `observed`、依据与适用条件：接受改写不代表实验通过，有待审修订也不自动证明旧知识错误。

### 本轮质量检查的精确范围

修改前 Duo 仅要求正文非空，不同来源的同正文可并存，缺少集中诊断入口。本轮 `GET /api/library/quality` 检查 active 正式知识：

- 空白、仅标题／注释的大纲、仅重复标题的正文提示缺少正文；短命令、链接、表格和代码保留，不设最小字数。
- 同 layer、完全相同 scope_key 内按正文哈希分组，只统一换行和首尾空行，保留大小写与代码缩进。
- 同正文仍可能有不同依据和适用条件，结果只提示复核，不修改知识、验证状态或原件。
- 最多扫描 2,000 条／32 MiB，显示最多 40 条空正文、40 组重复、每组 8 条；达到数量／大小上限明确提示。
- 不扫描未导入文件、归档、逐轮资料或真实知识根，也不判断语义重复。此功能不能证明用户本地目录已经清理完成。

## 2. MCP：统一注册，区分引用与维护能力

AHA2 `internal/backend/backend.go:38-65` 用后端中立 `MCPServer` 描述 transport、URL、环境变量和 bearer 引用；`internal/app/mcp_runtime.go:27-110` 解析任务绑定，由 `backend/codex.go:238-303`、`claude.go:183-229`、`dsh.go:322` 分别生成 CLI 配置。近期 `ce578f1`、`f064deb`、`89e69ba`、`2c570e4` 补齐窄渠道工具和 Codex 命名／允许列表。

`internal/agentapi/capability.go:14-83` 的 token 绑定 task／agent／turn、有期限、存哈希；`app/agent_control.go:66-84` 再核对轮次仍在执行。能力不能只靠工具名或提示词限制。

适合 Duo 的下一阶段设计：

| 能力 | 约束 |
|---|---|
| 引用：search／read／source | 只读，任务／项目范围，返回 revision、来源、适用条件，结果和正文有界 |
| 维护：propose／preview／review | 独立写能力，保留候选和原件基线，显式采用后才写入，冲突拒绝直接覆盖 |
| 后端注册 | 各引擎使用同一能力描述，分别验证工具允许列表、命名、凭据更新与会话恢复 |

可以由同一服务提供两组能力；是否拆成两个进程由部署和权限边界决定。MCP 负责接口，语义归纳仍需调用方模型或明确配置的模型流程。本轮没有新增通用知识 MCP，没有宣称所有新任务或其他引擎已接入。

Duo `hardware_mcp.go:68-79` 已对无 ID 通知返回 202 空响应，AHA2 的 `6b31183` 通知修复不是 Duo 新缺口。后续知识 MCP 可复用协议约束，但不能复用硬件令牌来获得知识写权限；未知工具也不应默认全量放行。

## 3. 任务、渠道与权限：回复应回到明确的来源

AHA2 `internal/httpapi/channel_mcp.go:25-65` 暴露窄 reply／decision／permission 工具；`:206-219,324-328` 将轮次、receipt 与消息哈希绑定请求身份。`internal/store/channel_events.go:61-65` 不再把 task_route 的一般回复自动镜像到渠道，减少内部进展误发群聊／私聊。

近期 `8de594b → 2f7fef1 → 285ca1c → 7362902` 实现群任务的 Owner 申请、折叠面板及回原群／申请人通知。`app/task_permissions.go:32-75` 限 action／scope／reason 及有效期；`store/task_permissions.go:89-113` 仅消费仍 pending 且未过期的申请。

这适合作为 Duo 多用户渠道的后续独立改进：入站身份与目标绑定、显式发信、稳定投递身份、一次性且有期限的权限。它不等同系统沙箱。Duo 已有 `codex_approvals.go` 的原生活请求和失效机制，不能由一条业务批准替代原生审批或永久授予全部能力。本轮没有改写飞书路由，也没有发送消息。

## 4. 执行：占用、计费、无活动与总时长分别表达

AHA2 `internal/httpapi/runtime_context.go:26-50,217-230` 区分最新请求占用和累计 usage；`domain/model_defaults.go:25-44`、`execution/executor.go:79,128-129` 提供 CLI 压缩阈值。Duo 已有 `RunContext` 到持久化与界面的链路，但原生 app-server 此前只发 billing usage，本轮补齐原生有效采样。

实现位于 `codex_appserver.go`：以 `tokenUsage.last.inputTokens` 和 `modelContextWindow` 生成 gauge，保留 thread／turn 身份过滤、同值去重，压缩后下降可见；缺失、非正、非法和越界数据不覆盖上次有效样本。没有采用模型默认窗口或将总计费当上下文。

AHA2 `backend/watchdog.go:12-17,48-117` 区分长轮次、无活动、警告和心跳；警告／心跳不重置真实活动计时。流传输的 idle timeout／retry 又是另一层。Duo 后续应继续分别呈现模型等待、原生重试、工具执行和审批等待，不因首文本超过一分钟就判任务失败。

最新 `3698996` 的 `app/runtime_selection.go:162-258` 修复模型 Env Group 解析，只有唯一匹配时复用，否则创建独立 group 并保留 secret 引用。Duo 应保持以当前模型驱动引擎、执行配置快照可追溯；本轮未确认 Duo 存在同一故障，不增加平行 Env Group 系统。

## 5. 工作区、硬件、桌面、自动助手与同步

- **工作区**：`workspace/runner.go` 与 local／WSL／SSH 适配隔离传输；`workspace/git.go:23-115` 区分非 Git 工作区和 task worktree。会话目录、原生恢复与 rollout 增量读取有参考价值，但需在 Duo 各环境中单独验证。
- **受管后台进程**：`managedprocess/manager.go:17-20,49-100` 按 task／name 限数量和输出尾部，适合开发服务，不证明 AI 子进程树全部停止。
- **硬件**：`hardware/manager.go:139-185` 按物理 targetKey 共享连接、拒绝参数不一致、多任务只读而最多一任务写。Duo 已有控制权和租约，应对照不变量完善，不重写用户设备配置。
- **桌面**：`desktop/manager.go:274-305,357-475` 检查 task／session／revision／turn claim 和 ActionID，拒绝过期观察及重放。Duo 也有 generation、expiry 和人工接管；知识引用不能变成桌面授权。
- **自动助手**：`app/pet_permissions.go:12-103` 区分知识查阅、维护与系统管理；`pet_task_watch.go:55-100` 对任务通知去重并在延迟回调复查状态。可借鉴真实任务关注与简报，不必复制宠物 UI。
- **同步**：`sync/engine.go:150-246` 对分页游标、依赖和无法应用的对象作明确处理，记录冲突后才隔离坏对象，避免一条坏数据长期堵住后续同步。`sync/business.go:413-440,739-761` 用墓碑防旧数据复活，不能直接替换 Duo 当前文件双向同步协议。
- **凭据同步**：`sync/crypto.go:23-85` 使用 Argon2id + AES-GCM；`secret_bundle.go:142-196` 将远端基础设施凭据作镜像，接管另行确认。Duo 本轮没有新增云同步，也没有导出凭据。
- **迁移**：AHA2 `store/migrations.go` 有 schema_migrations，但逐版本执行多条 db.Exec；不能仅因有版本表就宣称迁移已具备整版原子性。Duo 的数据库迁移应独立设计、备份和验证。

## 6. 不宜照搬的实现

1. **Windows writer 清理静态缺陷**：AHA2 `workspace/backend_writer.go:198-210,253-262` 遍历 PowerShell `$args`，所构建命令却未追加传入 PID，可能空循环并误报没有存活进程；未运行复现。`process_tree_windows.go:17-28` 也没有证明后代已全部退出。这些代码不能用来宣称解决 Duo 历史 `exit status 128`。
2. **过宽 CLI 权限映射**：`backend/claude.go:239-247` 的 auto 映射 skip-permissions，read-only 依赖工具 denylist；不能替换 Duo 的 sandbox／approval 分离约束。
3. **启发式模型容量**：`domain/model_defaults.go:15-44` 的默认 output 与压缩比例不是模型真实能力，Duo 保留未知窗口，不猜测。
4. **自动猜编码**：`httpapi/encoding.go:21-65,89-105` 对无效 UTF-8 尝试 GB18030，有大小／汉字条件；签名请求、二进制或严格 JSON 不能直接照用。本轮未改编码入口。
5. **把人工采纳或历史导入标成已验证**：仅说明进入知识库，不证明事实仍适用于当前代码、板子或版本。

## 后续实施顺序与验收

| 优先级 | 工作 | 验收重点 |
|---|---|---|
| 本轮 | 便签逐条置顶／颜色、只读知识检查、原生上下文 | 保存与刷新、颜色隔离、旧数据／导入、多窗口草稿、只读范围和协议计量 |
