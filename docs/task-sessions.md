# 分叉与重新打开任务

左侧任务三点菜单提供两个独立操作：

- **分叉会话**：创建新任务，复制截至此时的全部 Duo 对话、执行记录、关联附件、知识和增量记忆。分叉后记录分别保存，原任务保持不变。新任务沿用原环境、引擎、模型、权限和工作目录，但不会复用原生会话 ID；首次发送会提供固定的历史摘要和完整历史文本，再创建独立原生会话。复制记录不重复计入用量统计。
- **重新打开任务**：重新读取原任务及其历史，保留原生会话、草稿和服务端执行状态，不自动重发失败消息。

分叉前需结束执行及排队，确保复制的是完整记录。归档任务可以分叉出一个活跃任务；已删除任务不能分叉。分叉不复制飞书绑定、活动终端、设备连接、桌面控制授权或待答审批。超过 64 MiB 的历史归档会明确失败并回滚，不静默丢弃历史。

两个会话仍使用同一个工作目录；会话分叉不复制工作区文件或建立 Git worktree。模型上下文通过 Duo 保留的历史文本接续，不包含原生引擎未写入 Duo 的内部状态。历史附件保留在分叉记录中，可独立下载及引用；二进制内容不会自动重发给模型。

## 按任务 ID 重新打开

在左侧任务三点菜单选择“复制重新打开命令”，会自动填好当前程序路径、数据目录、任务 ID 和实际监听端口。也可以在运行中的 Duo 旁边手动执行：

```powershell
.\duo-service.exe --data "<Duo 数据目录>" --open-task "<任务 ID>"
```

命令只读检查已有配置和任务，然后用默认浏览器打开任务链接。需要已有服务在运行，并通过网页正常登录；不会启动第二个服务、初始化数据库、恢复已删除任务或重置对话。数据目录可在 Duo 设置中查看，任务 ID 位于“复制任务链接”的 `task=` 参数。

仅获取链接、不打开浏览器：

```powershell
.\duo-service.exe --data "<Duo 数据目录>" --open-task "<任务 ID>" --print-task-url
```

## 工具启动失败

`helper_unknown_error: setup refresh had errors` 表示 Codex Windows 沙箱尚未初始化成功，命令还没有执行。实际原因应查看 Codex 沙箱日志，不能直接认定 Git、项目或网络权限丢失。

本轮排查发现运行程序 `node_repl.exe` 的读/执行权限检查遇到文件占用（Windows 错误 32），导致初始化失败。这种全局工具运行问题不能靠重新加载某个任务保证修复。可在保存工作后正常退出占用运行程序的 Codex/工具宿主，再启动并重试。不要删除会话锁、清空数据或改成完全访问来掩盖错误。

参考 [官方 Codex Windows 沙箱说明](https://developers.openai.com/codex/windows/)。
