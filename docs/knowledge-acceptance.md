# Duo 知识功能：使用与验收

这份清单用于在升级后的 Duo 中验收完整流程，不表示本机运行服务已经升级、已有笔记已迁移，或真实模型已完成测试。先在“版本更新”核对实际运行版本，再按顺序操作；建议先用独立的验收任务与笔记文件夹。

## 你维护的两层资料

| 资料 | 保存位置 | 应看到什么 |
| --- | --- | --- |
| 每个任务的工作记录 | 实际执行环境的 `<workspace>/.duo/tasks/<任务名-稳定短ID>/任务记录.md` | 当前目标、计划、进展、决策、证据、阻塞、下一步，加按时间记录的关键变化和逐轮来源 |
| 跨任务长期知识 | 自选 Obsidian 笔记根，下面分平台共识、系统知识、项目知识 | 一篇可独立阅读的主题文档，包含方法、依据、适用条件、来源和标签 |

平台共识只收用户明确约定的跨任务习惯与流程；通用原理和方法归系统知识；特定项目的操作、资料和结论归项目知识。凭据正文不进入知识，写受保护配置的引用。Duo 数据库仍保存正文快照、身份、修订与来源，并与 Markdown 双向同步。

## 1. 先配置，再分别保存

打开顶部唯一入口 **知识库 → 目录与整理**。页面里的“第一次使用与验收顺序”可随时展开。

1. **1. 笔记根目录与知识分类**：选一个专用目录，例如 `<Obsidian>/Duo知识`；新配置使用“所选目录就是知识根”。开启“三类知识的 Markdown 同步与索引”，点“保存知识库路径与同步设置”。三个分类是同一根下可自定义的相对目录，不能互相包含。
2. **2. 任务记录与每轮候选**：开启自动记录、随正常回复整理任务状态与候选、自动读取，再点此组“保存设置”。这些开关不负责搬迁旧笔记；没有单独的“工作区记忆”界面开关。
3. **3. 将候选整理进笔记**：可开启每轮自动归档，也可开启 1～168 小时的定时整理，点“保存整理方式”。默认间隔 24 小时，定时整理需要 Duo 运行。

验收：三个设置组并列、各自保存；切换“阅读知识”和“目录与整理”不会丢掉尚未保存的草稿。页面显示实际知识根，文件同步无错误时再去笔记目录检查三类首页。

## 2. 命名任务，检查同一份工作记录

1. 新建一个有明确名字的任务，选固定工作区。例如“知识功能验收”，要求 AI 先写目标与验收标准，再分两步处理一个小问题。
2. 左侧任务行 **⋯ → 任务记录**，直接阅读任务 Markdown。旧任务没有主文档时点“回填 / 同步本任务已有记录”；这只回填已保存资料，不额外调用模型。
3. 查看文首当前状态、下方时间进展及“逐轮来源与历史资料”。历史较长时有分页，不应为每次提问另建一篇正式知识。
4. 点“编辑 Markdown”，在自动受管区之外加一条备注，保存；重新读取后备注仍在。文件位置显示真实相对路径，也可从任务菜单“在 VS Code 中打开”访问该工作区。
5. 在“知识项目范围”选择或创建稳定项目，保存。任务改名、换引擎后仍按此项目检索；目录名首次落盘后保持稳定，改任务名不会反复搬动目录。

验收：明确目标与计划来自实际进展，不能把“你好”当目标。没有有效结构化状态时保留旧状态和原始来源，不凭空写完成。执行期间的公开观察有快照；正常公开进度可以携带合法任务状态增量，随有新事件的最多 15 秒快照合并。没有增量则保留旧状态，不要求每一条进度都产生语义变化。完成步骤和证据仍需逐字来源，这不是 Duo 独立复测。

人工修改受管区域后，该区域暂停自动替换并提示；其他区域和按来源追加的历史独立维护。两端同时改文件时拒绝旧版本保存、保留草稿，不应悄悄覆盖。Windows、WSL、SSH 分别写各自实际工作区，远端写失败会提示，不会改写本地同名路径。

## 3. 切换模型与引擎，验收交接

1. 先让 AI 在原任务记录中明确“当前完成了什么、哪些未验证、下一步做什么”。
2. 用输入框旁选择器换模型；通常延续原生会话。换引擎时先查看交接范围与提示，再确认并发送下一条消息。
3. 让新引擎复述目标、最新进展、未决问题和备注，核对是否与任务文档一致，再继续工作。

验收：同一个工作区、同一个任务 Markdown 保持；新原生会话读取有界任务摘录，继续会话只补文档变化，未变内容不重复发送。失败请求不确认读取进度。同工作区任务可以参考彼此交接资料，但不会自动发送所有任务全文。

真实多引擎理解质量需要你实际验收。不同引擎原生会话不能互换；文件交接不含旧图片二进制，不能保证任意模型无损理解全部历史。“会话与恢复 → 高级会话恢复”用于异常恢复，不是日常切引擎入口。

## 4. 分清两种历史整理

在 **知识库 → 阅读知识** 选择分类和任务范围。按钮旁显示实际范围。

| 操作 | 处理什么 | 是否另起模型 |
| --- | --- | --- |
| 每轮随正常回复整理 | 本轮任务状态和有依据候选 | 不另起，但增加本轮输出 |
| 自动 / 定时 / 一键整理已有候选 | 已保存的结构化分层结果 | 否 |
| 用 AI 整理本任务 | 该任务尚未整理的终态聊天，包含失败、停止 | 确认后调用，消耗额度 |
| 用 AI 整理此主题 | 当前笔记正文、依据、条件和该主题全部待修订 | 确认后调用，消耗额度 |

“一键整理已有候选”遵循当前分类及任务范围；选“平台共识”不会同时整理系统和项目候选。“用 AI 整理本任务”按任务提取三类知识，不受当前查看分类限制；未选任务范围时使用当前已打开任务，没有可用任务会提示选择。

AI 历史整理先显示剩余轮数，一批最多 16 轮；确认使用所选任务的引擎与模型后排队，可在任务执行记录看进度。成功保存有效结果后才推进该批来源；没有新资料不再请求模型，再次点击继续下一批。独立整理支持 Codex、Claude Code、Harness；其他引擎仍可随正常回复提供候选。

验收：多次整理同来源、同内容不会重复生成笔记；同主题新内容进入待合并修订。候选默认待验证，没有资料不凑篇幅。整理完成只表示结果入库；点“刷新文件”检查独立的 Markdown 同步状态，看到错误或冲突不能当作已经写到 Obsidian。

## 5. 把碎片修订整理成主题文档

1. 打开有“查看待合并修订”的笔记，先读原文，再看默认展开的候选、依据和适用条件。
2. 一条完整且有据可查的修订，可直接“采用修订”；无价值的候选可“忽略修订”。
3. 多条候选需要组织时，选一个支持整理的任务，在笔记里点“用 AI 整理此主题”。确认会发送当前主题及修订并消耗额度，再排队启动。
4. 执行结束后刷新文件、重新打开此主题，查看“完整合并稿”和覆盖的候选数，核对后采用。原文在采用前保持不变；采用后退回待验证，并移除合并稿已覆盖的候选。
5. 无依据的冲突应留下未决事项。生成候选后原文有变，会显示基线变化并禁止直接采用，重新整理后再判断。

验收：主题合并不会继续硬件调试，不让 AI 验证没执行过的实验，也不自动选择矛盾说法。同样不保证 AI 保留每个细节，必须阅读合并稿。当前正文过大、任务不允许写入或引擎不支持时会提示；此时保留原文，可先人工编辑或缩小主题。

## 6. 迁移笔记目录，先预览

仅首次配置根目录时使用第 1 组；要搬已有知识，用 **4. 迁移已有知识到新目录**。

1. 先“立即同步 / 重建索引”，处理全部冲突。若原根还有未同步修改，迁移预览会阻止继续。
2. 选择一个新的专用空文件夹和根目录方式，点“预览迁移”。目标可以是空目录，或只有此前同内容复制文件；不同内容和清单外普通文件均会阻止迁移。
3. 核对来源、目标、文件数、字节数、待复制/相同/冲突清单，再点“确认迁移并切换目录”。
4. 成功后实际根目录更新，旧目录保留。身份、来源、修订和相对链接随复制保留；三类相对目录不在此步骤改名。

验收：修改目标后旧预览立即失效；取消确认不写入；确认后源、数据库或目标发生变化会停止并要求重预览。服务端失败不切根，已复制的同内容文件可在重新预览后跳过续传；如果确认请求中途断网，先重新打开设置核对实际根，不能把未收到响应当作确定未迁移。迁移不是语义重整，不会自动将独立旧阅读视图合并成正式知识，也不迁移原生 CLI 会话、任务工作区或完整 Duo 数据。

## 7. 外部编辑与同步

1. 先复制一篇验收用笔记内容作对照，在 Obsidian 中修改正文、保存。
2. 在 Duo 点“刷新文件”或等待每分钟同步，重新打开此笔记，应看到修改；实际正文外部变化会回到待验证。
3. 在 Duo“编辑正式知识”修改后保存，再刷新，Obsidian 应显示修改。
4. 如两边同时修改，查看显眼同步提示和设置里的冲突详情；核对两端内容后处理，不能直接忽略冲突宣布同步成功。

仅修改 YAML 状态不会自动取得“已验证”。标记已验证是用户确认依据与适用条件，不代表 Duo 实际运行了实验。跨电脑由 Obsidian/Git 完成同步，每台 Duo 设置本机路径；只同步笔记不等于同步整个工作环境。

## 8. 查找、引用与图谱

在“阅读知识”按分类、任务、关键词、标签查找；打开主题手册后可通过原笔记链接编辑。点“引用”把带来源的有界摘录加到当前输入框，发送前仍可修改。

“关系图谱”显示文档与标签的关系，支持缩放、点标签筛选、点文档阅读编辑。最多展示 80 份文档与 20 个标签；更多内容先缩小范围。它不是因果图或语义检索。AI 相关知识检索当前为有界关键词匹配，项目范围会约束召回；待验证只能作为调查线索，不能冒充当前实际验证。

## 自动检查覆盖与人工验收边界

合成网页回归覆盖设置/草稿保存、迁移预览与确认、冲突阻止、指纹失效和重复锁、主题整理调用范围、原文基线变化拒绝采用、异步视图隔离、同步错误显示，以及内部 `task_state` 不渲染成对话 JSON。相关用例：`Test-Knowledge-Completion-Web.mjs`、`Test-Knowledge-Organization-Web.mjs`、`Test-Knowledge-Graph-Web.mjs`、`Test-Knowledge-Layers-Web.mjs`。这些测试使用内存资料，不访问真实模型或用户笔记。

真实模型提取质量、多引擎接续理解质量、你的真实笔记目录同步及跨电脑 Obsidian/Git 流程，需要按上述清单人工验收。自动矛盾裁决、无人值守付费语义整理、向量/GraphRAG、技能或 MCP 自动转化不属于已完成能力。
