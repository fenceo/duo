# 飞书中间过程与问题卡片

v0.34.0 起，已绑定任务的飞书执行卡片会显示最近 6 条中间过程，每条有长度上限；完成后仍保留近期过程和最终回复。中间过程来自引擎公开的进度事件，不转发内部日志或工具全文。卡片按约 2 秒合并更新，不是逐 token 流式推送；任务较多或接口限流时会延后。

Codex 的同步提问和异步提问有独立的飞书卡片。普通问题可选择选项、填写补充并一次提交全部答案；本轮结束后仍待回答的异步问题也会通知。表单填写中不反复刷新；网页或飞书回答后，卡片会更新为已关闭。

v0.34.1 修正了题目布局：JSON 1.0 的表单容器不能直接内嵌 `div` 文字组件，题目、说明及控件现在放在单列分栏中。v0.34.0 可能出现卡片接口成功返回消息 ID，但客户端只显示外层提示的情况。消息发送成功不等于内容渲染或答案回传已验证。表单需要飞书 V6.6 及以上客户端，详见[官方表单容器规范](https://open.feishu.cn/document/feishu-cards/card-components/containers/form-container)。

执行中的异步答案立即引导当前轮次；没有活动执行时开始下一轮。原生接收未确认时不改为排队，也不重发成新轮次。飞书回调等待确认最多约 1.5 秒，慢响应可能先显示“尚未确认”；请检查任务状态，必要时重试原答案。重复点击、切换任务或原生会话后的旧卡片不会重复提交。

敏感输入、权限审批、超过飞书尺寸限制的表单只发送处理提醒和网页入口，不在飞书直接批准操作或收集秘密。结构化提问目前沿用 Codex 接口，其它引擎仅转发已有公开进度与回复，不把普通问句推断成可回答表单。

v0.34.12 起，Harness 官方工作区模式产生的原生单次审批也会发送独立的飞书处理提醒和当前任务网页入口。在 Duo 网页批准本次、拒绝本次或取消后，原生执行收到对应决定，飞书卡片随之关闭。停止、归档、删除或切换绑定任务后的旧请求不再通知；飞书问题表单不能替代权限审批，也不会创建额外对话轮次。

独立问题通知保留消息 ID、创建 UUID 和重试状态，不重复创建通知；卡片持续失败时退为文字提醒与网页入口。投递同时核对机器人、绑定用户和当前聊天任务。更换机器人不会把旧机器人的问题发送到历史聊天；升级前无已知聊天归属时，在飞书发送一次 `/任务` 并进入目标任务即可建立归属。

若能收到消息但无法点击卡片，请在飞书开放平台检查 **事件与回调 → 回调配置 → `card.action.trigger`**，接收方式为长连接。Duo 扫码创建机器人已申请此回调；手工创建或较早配置的机器人需要检查并发布配置。还需保留机器人发送消息权限。参考 [飞书官方回调说明](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-card-action-reply.md) 和 [表单输入示例](https://open.feishu.cn/community/articles/7271149634339454978?lang=zh-CN)。

回归使用模拟 API、结构化回调和本地原生协议 fixture；未向真实飞书会话发送测试消息，也未调用真实模型。
