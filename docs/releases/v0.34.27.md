# v0.34.27

- “切换 AI”增加 Codex 新会话恢复选项：保留原聊天和旧原生会话，使用有限的本地笔记、共识及最近成功回复接续，不重新注入全部工具日志。先检查预览，再确认切换；发送下一条消息时才调用模型。
- Codex 原生重试显示为执行进度，并保留当前线程、轮次的结构化原因。可辨识的服务繁忙或 429 不再只显示为“Reconnecting”。
- 最终响应流断开时附上此前实际观察到的重试原因，帮助区分服务繁忙、限流和连接中断；Duo 不自动重发整轮任务。
- 执行端清理失败增加有界、固定类别的诊断，不输出原始命令日志，也不更改进程终止规则。保留模型请求的原始失败原因。

新会话恢复用于绕开旧上下文的压缩失败，不能保证服务繁忙时请求成功。只保留有限的接续资料，遗漏的细节可从原聊天或工作区补回；没有用户确认不会更换当前原生会话。加长延时测试的等待上限不能阻止已收到的 429 或服务端主动断流。

验证：Go 全量测试与 vet、TypeScript 检查、43 项网页回归通过；恢复界面通过桌面、390 和 320 像素布局检查。合成回归覆盖旧会话保留、下一轮建立新会话、超过 64 MiB 历史的有限接续、陈旧预览、重复提交和重试诊断，不使用真实模型。
