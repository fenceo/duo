# v0.14.0

模型列表不再只认官方缓存，选模型也改成了点开就能挑、能搜索、能直接输入的方式。

## 修复：读不到第三方模型

`config.toml` 里用 `model_catalog_json` 指向自定义模型目录时（cockpit 一类的中转配置），Codex 不会生成 `models_cache.json`，之前这里读不到任何模型。现在按顺序读：

1. `config.toml` 中 `model_catalog_json` 指定的文件（相对路径按 `~/.codex` 解析）
2. 环境设置里填写的模型缓存路径
3. `~/.codex/models_cache.json`、`model_catalog.json`、`cockpit-model-catalog.json`

多个文件会合并去重，单文件超过 4 MB 跳过；`visibility` 不是 `list` 的模型（例如 `codex-auto-review`）继续过滤。Windows、WSL、SSH 三种环境走同一套候选顺序，界面上的「模型检测详情」会写明命中哪几个文件。

## 改进：像 IDE 插件那样选模型

- 新建任务里，「模型」变成一行可点的按钮：点开是列表，顶部可以直接搜索，也可以输入列表里没有的名字。
- 每个模型下面会标注它在目录里的原始名称，默认模型一栏保留「使用此工具的默认模型」。
- 任务打开后，底部输入框左侧的模型标签同样可以点开，模型和推理强度在同一个菜单里改，改完立即生效并写回任务。
- 推理强度会跟随所选模型的支持范围（来自模型目录），第一档是「工具默认」，用于还原成不指定；模型不支持时给出一句说明。
- 搜索只在没有任何匹配时才给出「使用「输入的名字」」，避免输入半个词就误把词本身当成模型名。
- 「AI 工具」和「推理强度」并排放在新建任务表单里，切换 Codex / Claude Code 会重新拉取对应的模型列表。

任务模型接口 `PATCH /api/tasks/{id}` 现在同时支持 `model` 和 `reasoning_effort`，推理强度对旧任务会自动补建执行记录。

## 下载

下载 `Jianzuo-portable-windows-x64.zip` 后完整解压，双击 `简作.exe`。`Jianzuo-portable-windows-x64.zip.sha256` 用于校验下载完整性。

已有用户：先退出程序并备份 data，替换程序文件时保留 data。模型列表每次都从所在环境重新读取，升级不需要迁移。
