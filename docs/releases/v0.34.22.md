# Duo v0.34.22

- 修复 WSL MiMo Code 在 v0.34.21 选择模型后启动失败的问题：WSL 默认 shell 会解释临时 JSON 配置中的引号及特殊字符，使官方 CLI 在连接模型前报 `ConfigJsonError`。ACP 启动改为直接执行，原生结果导出也避免额外 shell 解释，保留所选发行版、用户及最小宿主环境。
- 保留 MiMo 配置解析失败的安全原因，避免最终 `--- End ---` 覆盖故障并只显示 `<nil>`。错误不回显配置内容、Key 或原生异常中的敏感字段。
- 不修改已有 API、权限配置、会话数据和历史；升级后可在原任务重试，无需重建任务或重新填写 Key。

回归覆盖含 JSON 引号、换行、空格、单引号和 shell 特殊字符的参数传输，以及配置失败后进程停止和错误脱敏。隔离 WSL 官方 CLI 回归使用假 Key 和本地模拟 API，不调用真实付费模型。

验证：Go 全量测试、vet、TypeScript 检查与构建、40 项网页回归及 139 个桌面/窄屏界面用例通过。官方 MiMo 0.1.15 的 Windows 与 WSL 隔离回归通过；WSL 覆盖 `mimo-v2.6-pro` / `mimo-v2.6-flash`、短回复、同一会话历史恢复及原生结果导出。
