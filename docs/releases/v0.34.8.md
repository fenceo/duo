# v0.34.8

修复 Harness 配置 API 后新建任务仍无法读取模型的问题，并补齐认证验证与模型发现。

- 环境与引擎 → Harness → 配置 API，增加“验证并读取模型”和模型选择列表；支持新 Key，以及留空使用已保存的 Key。
- 保存时从所选 Windows / WSL / SSH 环境请求服务商模型列表，认证或网络失败会明确提示且不保存。不支持标准模型列表接口的服务商可以手动填写模型 ID 保存，界面明确标注尚未验证。
- 支持 OpenAI Chat Completions、Responses 和 Anthropic Messages 的模型列表认证；读取 Anthropic 分页，不跟随重定向发送 Key。仅请求模型列表，不发送推理请求，列表认证成功不代表每个模型均可调用。
- 发现的模型写入目标用户的原生 Harness 配置，保留其他 provider、凭据和工具；更换 API 地址时不沿用旧地址的模型。
- 新建任务与模型选择器读取目标环境的 `cordis.patch.yml`，兼容旧 `settings.yaml` 及独立 `DSH_HOME`；WSL / SSH 不再只依赖 Duo 的默认模型配置。
- 保存后更新界面模型目录，保留失败时的配置草稿；关闭窗口或退出登录清空 Key。保留原生配置备份、锁、环境变更检查和失败回退。

升级后进入对应环境的 Harness API 配置，点击“验证并读取模型”，确认默认模型，再点击“保存并读取模型”。新建任务选择该环境和 Harness 即可读取保存的列表；已运行的 Harness 仍可能需要重新打开。没有自动修改现有任务或重启环境。

回归使用合成 Key 和回环模拟 API；真实 WSL 已安装 dsh 在隔离目录中完成模型发现、原生保存、任务目录读取和 ACP 回复，不调用付费模型。
