# v0.34.31

- 新增 ZCode（智谱 Z.ai / GLM 官方 CLI）检测：Windows 上查找 PATH 里的 `zcode`/`zcode.cmd`/`zcode.exe`，以及 ZCode 桌面内置的 `resources/glm/zcode.cjs`；WSL/SSH 上查找 PATH 与常见安装位置。环境扫描与引擎目录会显示“已安装/未安装”，路径不写入任务或配置。
- ZCode 目前只检测，不安装、不登录、不运行任务：CLI 使用自有 ZCode Protocol 与自有会话存储，`--prompt/--json` 的输出结构尚未在真实模型调用下核实。核实前不按“已接入并验证”开放，也不猜测参数拼接或会话续接。
- 想用 GLM 完成任务仍走已核实的路径：Claude Code 的 Z.ai/GLM（Anthropic 兼容）预设，或在目标环境用 `opencode auth login` 配置 Z.ai 后选择 OpenCode（模型目录由 `opencode models` 读取，Duo 不保存 Key）。
- 修正硬件授权对话框的引擎说明：v0.34.30 起 MiMo Code 已按原生 HTTP MCP 能力挂载本轮凭据，对话框不再写“MiMo Code 的硬件工具尚未接入”，并说明未声明该能力的 CLI 会被明确拒绝。
- 对本次改动的 Go 文件执行 gofmt。文档补充 ZCode 的能力边界与其现有替代路径。

验证：Go 全量测试与 vet、TypeScript 检查与构建、网页回归通过。新增回归固定“检测级引擎不可选、不可自动安装、Transport/能力声明与实现一致”，并用合成探测输出（含 ZCode 路径行）验证环境状态解析与失败回退；未调用模型、未读取真实设备或账号凭据。真实 ZCode CLI 是否可用仍需在装有该 CLI 的环境确认，其运行适配器待输出结构核实后另行发布。
