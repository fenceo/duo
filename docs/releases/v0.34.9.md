# v0.34.9

Harness 新建任务按官方默认权限档位呈现，并接入原生单次审批。

- DeepSeek Harness 提供“工作区权限”和“完全访问”。工作区权限对应官方 `workspace-write + ask`，允许工作区和原生允许的临时目录内写入，需要提升权限时询问；完全访问对应 `danger-full-access + never`，不请求批准。
- Harness 不再显示 Codex 专有的“帮我批准”或额外的只读预设。Codex 保留原有权限与原生自动风险评审。
- 将 Harness ACP 的权限请求接入 Duo 待处理卡片，展示执行环境、工作目录、本轮工具和原始参数。支持批准本次、拒绝本次和取消请求；不创建永久授权或无条件自动批准。
- 审批关联当前会话的本轮工具，缺少详情、跨会话、重复标识或过多请求均不获授权；停止、断线和本轮结束后请求失效。文件与终端仍由原生 Harness 执行。
- 旧 Harness 任务及自定义模式继续保留此前的权限语义，不因升级开启审批或扩大访问。要使用官方工作区审批，请新建任务，或在停止后通过“切换 AI”明确选择新的工作区权限并接续历史。

回归覆盖单次批准/拒绝、请求失效、任务隔离和界面切换。已安装的 WSL Harness 使用隔离配置和回环模拟 API 验证批准执行无害命令、拒绝阻止执行；不使用真实 Key，不调用付费模型。
