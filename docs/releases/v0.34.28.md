# v0.34.28

- 新增 OpenCode 引擎：通过官方 `opencode acp` 原生 ACP 协议调用，支持创建与恢复原生会话、流式输出、模型切换、附件与图片、单次工具审批和取消。Windows、WSL、SSH 都提供检测与一键安装（npm 包 `opencode-ai`，安装到独立目录并校验版本后才切换路径）。
- OpenCode 直接复用原生会话：停止、闲置、服务重启后发送消息会恢复同一原生会话；恢复失败保留原会话标识，不自动新建空会话，也不重放 Duo 的显示历史。
- OpenCode 支持 Duo 桌面/硬件工具：按任务授权后通过 `session/new` 的 HTTP MCP 挂载本轮凭据，凭据随轮次更换，收回权限立即生效；CLI 未声明 HTTP MCP 能力时明确拒绝而不是静默降级。硬件授权文案同步说明适用范围。
- OpenCode 模型目录读取该环境的 `opencode models`，并与本机显式配置的模型合并；新建/恢复会话时只接受原生会话声明的模型，目录以外的模型给出明确错误而不是静默运行另一个模型。
- OpenCode 不提供 ACP 权限档位：只读任务自动拒绝工具授权请求，其他任务按 Duo 的单次批准/拒绝处理，完全访问仍会为每次工具请求确认。OpenCode 的独立知识整理尚未接入，会明确拒绝而不是以普通聊天权限代替。
- 引擎检测、环境扫描、安装/更新入口、账号与审批界面、权限提示和文档都补上 OpenCode；同时修正文档中“Harness 仍不支持硬件工具”“MiMo 尚未开放运行”等过时表述，并拆开 Kimi 与 MiMo 的能力说明。
- 修复/整理：把 MiMo 与 OpenCode 共用的原生 ACP 启动器、`--exec` 目标命令和环境注入改为引擎中立命名，不改变 MiMo 现有行为。

验证：Go 全量测试与 vet、TypeScript 检查与构建通过。新增合成 ACP 回归覆盖 OpenCode 的握手能力校验、同一原生会话的跨轮恢复、工作目录传递、模型目录校验、只读/知识任务的准入拒绝、HTTP MCP 凭据随轮更换、CLI 缺少 HTTP MCP 能力时失败关闭，以及审批使用独立的 `opencode/requestPermission` 方法；全部使用合成 fixture，不调用真实模型、不读取账号。

云端验收发现一项网页回归仍固定匹配“知识整理按钮只禁用 MiMo”的旧源码文本，新增 OpenCode 后该断言失配。断言改为匹配新的引擎列表，产品行为不变；全部网页回归在本地重新逐项通过。
