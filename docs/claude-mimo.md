# Claude Code 与 MiMo 配置

在“环境与引擎”中先检测并安装对应环境的 CLI，再点击该行“配置 API”。它直接打开所选环境的独立配置窗口，不进入账号管理。两个工具都支持官方服务或自定义兼容服务；引擎决定执行方式，API 服务决定实际调用哪个模型。

服务预设按引擎展示：未配置的 Claude Code 默认选择 Anthropic 官方 API；也可选择 Z.ai / GLM、自定义 Messages 服务或 MiMo 兼容 API。MiMo 的套餐和区域只在选中 MiMo 服务后展开，不在主预设中重复列出。已保存的服务会正确回显；切换到另一服务会清空旧模型和待输入的 Key，需重新读取模型并填写该服务的 Key。打开另一个引擎的窗口时立即重置表单，读取失败也不会显示上一个引擎的配置。

## Claude Code

需要 Anthropic Messages 兼容服务。官方 Anthropic API 可选择官方预设并留空地址，使用 `x-api-key`。第三方地址通常使用 Bearer Token；服务若要求 `x-api-key`，在请求头选项中选择 API Key。MiMo 按量付费预设使用 `https://api.xiaomimimo.com/anthropic`；Token Plan 的区域地址与 Key 以订阅后台为准。

Z.ai / GLM 预设使用官方 Anthropic 兼容入口 `https://api.z.ai/api/anthropic` 和 Bearer Token（保存为 `ANTHROPIC_AUTH_TOKEN`），角色默认“统一使用主模型”，模型 ID 以服务商目录或订阅页面为准（例如 GLM 编码套餐的 `glm-4.6`）。部分服务以 HTTP 200 返回错误对象（例如 `success:false` 加错误码）；Duo 会把它显示为验证失败并阻止保存，只回显错误码，不回显原始响应或 Key。目录接口不可用时按服务商能力选择：返回 404/405/501 允许手动填写模型 ID 保存；返回其他 200 内容则判定为无法识别的目录并阻止保存。

配置窗口可以选择生效范围。新配置默认建议“仅 Duo 生效”：在目标 Claude 配置目录保存独立 `duo-api.json`，每次由 Duo 启动时通过 `--settings` 加载。它只覆盖 API 路由和模型角色，不改原生登录文件、权限、MCP、工作区信任或历史目录，也不改变 `CLAUDE_CONFIG_DIR`。已有任务下次执行使用当前配置，仍恢复原会话。原生配置中的托管策略继续生效。

“整个环境生效”延续原有行为，写入该环境的原生 Claude 配置，其他 Claude 会话也会使用。API 会替换当前订阅登录，原文件和登录保存在备份中，账号库存不删除。旧配置保留原范围，不自动迁移。切换范围可以保留同一服务的 Key；停用 Duo 专用引用后保留它的文件，不删除历史或重建会话。需要结束该环境的 Claude 执行和排队任务后才能保存。

展开“模型角色配置”可选择统一使用主模型、分别配置角色或使用原生角色默认值。分别配置支持 Opus、Sonnet、Haiku、可选 Fable 和子代理模型；前三项留空跟随主模型，Fable 留空使用原生默认，子代理留空遵循 Claude 代理规则。主模型也为空时相应角色采用原生默认。每个 ID 必须由当前服务支持；不是为每个角色保存一把 Key。同一 API 服务的一把 Key 由这些角色共同使用。切换到另一服务预设会清空旧角色映射，防止请求旧服务的模型名称；手动修改自定义地址时，请核对模型 ID 是否仍适用。

Duo 专用配置的任务模型列表读取主模型和角色 ID，不混入其他原生账号的列表；这只表示已配置，不保证模型可调用。付费测试会明确显示当前服务，并核对专用配置是否已变化，过期列表必须重读后重新确认。

官方依据：[Claude 模型角色](https://code.claude.com/docs/en/model-config)、[会话设置与优先级](https://code.claude.com/docs/en/settings)、[Claude CLI 参数](https://code.claude.com/docs/en/cli-reference)。

## MiMo Code

选择官方 MiMo Code，引擎通过 `mimo acp` 执行。当前官方独立发行与旧 npm alpha 包的接口和配置格式不同；一键安装使用当前官方发行。

MiMo 模型选择 OpenAI Chat Completions，根地址通常包含 `/v1`。当前 MiMo CLI 会把 MiMo 模型固定到 Chat Completions SDK；不能为这些模型选择 Anthropic Messages 根地址。其他兼容服务的非 MiMo 模型仍可使用 Anthropic Messages，填写包含版本路径的根地址。地址按服务商给出的值填写，不把 Responses 接口当作 Chat Completions 接口。Token Plan Key 和按量付费 Key 不能混用；订阅套餐使用套餐页面给出的区域根地址。

点击“保存并读取模型”后直接用于所选环境，无需添加账号或再激活。新配置保存为目标原生配置目录中的 `duo-api.json`，Duo 通过 `MIMOCODE_CONFIG` 引用，保留其他原生配置。MiMo 会话仍保存在目标用户的原生数据目录，切换 API 不移动历史。若已激活 v0.34.18 的 MiMo 库存配置，窗口会读取并更新它，不创建重复库存或删除旧引用。配置模型在原生目录中显示为 `duo-mimo/<上游模型 ID>`；上游 ID 中的 `/` 会保留。

使用 Duo API 配置时，任务列表选择 `duo-mimo/` 路由的模型，避免误用未配置 Key 的内置提供商。官方模型目录中的专用 ASR/TTS 型号用于转写/合成，不能执行代码会话，因而不列入此选择器；并未卸载这些模型或禁用语音服务。重新保存旧配置可刷新原生目录和 MiMo 思考/工具续接元数据。

每轮结束后，Duo 停止该轮原生写入进程，再读取 CLI 保存的本轮结果，核对会话、输入和所选模型；补回 ACP 未发出的短回复并投影认证、额度或接口错误。只采用当前输入对应的最终消息，不把旧回复或工具前言当作最终回复。原生记录读取失败时保留流式记录并提示，不清空历史或新建替代会话。过程显示合并连续思考片段和累积正文快照，保留工具步骤；轮次底部显示所选模型和原生用量。模型自述或默认配置文件不代表本轮实际路由。

任务提供 Build、Plan 和原生 allow 权限。Plan 遵循 MiMo 的原生规划代理规则；允许联网，不能把它当作操作系统只读沙箱。需要人工决定的原生工具请求可以单次批准、拒绝或取消；原生明确的 ask/deny 规则保留。所选代理和权限在下次消息发送时生效，当前执行不变。

## 验证与模型列表

“验证并读取模型”从所选 Windows/WSL/SSH 环境访问模型目录接口，只发 GET，不消耗推理额度；保存时也会自动验证。成功说明模型目录认证通过，具体模型调用仍未验证。服务若没有标准模型列表接口，会明确提示并允许手动填写模型 ID。Key 不回显；留空保留同一服务已保存的 Key。改变地址、协议或认证方式需要重新填写 Key。保存配置前需结束该环境对应引擎的执行或排队任务。

MiMo 已配置 Duo API 时，新建任务与已有任务的模型目录实时查询所选服务的 `/models`，不再只读取上次保存的 CLI 目录。读取目录只发 GET，不更新配置或发送推理请求；没有标准目录接口时明确显示原生配置回退。目录不包含专用 ASR/TTS，提示中区分服务端总数和代码会话型号数。新发现模型在下一轮进程覆盖中注册，并同步该进程默认模型，原配置文件和原生会话目录不变。

MiMo 的“测试 API 模型”逐项发送最小文本请求，无工具、项目文件、任务历史或附件；测试前确认当前 API 服务、模型范围及额度使用，可取消剩余测试。地址、协议或 Key 变化后需要重新读目录并确认测试；缺少配置时不能测试。结果只代表 API 文本调用，不保证原生 CLI 的工具能力或长会话表现。Key 和原始错误载荷不回显。MiMo 独立知识整理仍未接入，不以普通聊天权限代替。

MiMo 任务获得设备授权后，Duo 在原生 `session/new`（或恢复会话时）声明本轮 HTTP MCP 工具地址与凭据，凭据只对应当前一轮，收回授权立即失效。MiMo Code 的原生 ACP 是否声明 HTTP MCP 能力由 CLI 版本决定：声明时才挂载，未声明时明确拒绝本次执行并提示升级或先收回授权，不会在缺少工具的情况下静默运行，也不会把凭据写进启动参数、环境变量或原生配置。

官方依据：[MiMo Code](https://github.com/XiaomiMiMo/MiMo-Code)、[MiMo 在 Claude Code 中使用](https://mimo.mi.com/docs/zh-CN/tokenplan/integration/claudecode)、[Claude Code 网关配置](https://code.claude.com/docs/en/llm-gateway-connect)。
