# Duo 的任务记忆与知识分层

任务过程用于接续工作，正式知识用于长期复用。自动记录不等于已经验证的知识；引擎原生会话、Duo 数据库和 Markdown 各有用途。

## 四层资料

| 层级 | 内容 | 主存储与同步 | 使用方式 |
|---|---|---|---|
| 工作区任务资料 | 用户要求、回复、失败原因、逐轮来源与交接摘要 | 任务实际执行环境的 `<workspace>/.duo/tasks/<任务名-短ID>/`；完整记录仍保留在 Duo 数据库 | 新会话读取同工作区的有界交接资料；完整记录可在任务菜单查看 |
| 平台共识 | 工作习惯、NFS 调试、烧录约定等跨任务方法 | Duo 数据目录内的数据库；开启 Markdown 同步后镜像到 `Duo/consensus/` | 仅用户确认的已验证条目自动供新会话参考 |
| 系统知识 | 概念、原理、方法、学习总结 | 指定 Obsidian 根目录下的 `Duo/system/<主题>/` | 在知识库浏览、搜索并引用 |
| 项目知识 | 项目结论、操作资料、问题解决与资料索引 | 指定 Obsidian 根目录下的 `Duo/projects/<项目>/` | 按项目浏览、搜索并引用 |

系统及项目目录名含稳定短标识以避免重名。知识管理以数据库维护修订及来源，并与 Markdown 双向同步；不能把尚未同步的数据库修改视为已经写入 Obsidian。平台共识随完整 Duo 数据迁移，也支持通过 Vault 导入；从另一台电脑首次导入的正式知识为“待验证”，需在当地重新确认。

正式知识改标题或范围后，启用分目录同步时仅在旧文件未被外部修改、目标路径空闲时安全移动；否则沿用原路径并保留内容，不创建重复正文。索引读取实际文件位置。旧版任务主文档仍保持首次导出的文件名。

## 从哪里设置

打开顶部 **知识库 → 积累设置**：

1. 设置积累根目录，可以选择已有 Obsidian Vault。Duo 只管理其中的 `Duo/`。平台共识、系统知识、项目知识各有可自定义的相对目录，默认为 `consensus`、`system`、`projects`；启用同步并保存时创建三个目录。不填写根目录时仍可使用本地默认知识目录，但一键提取前会要求明确配置路径。
2. 启用 Markdown 同步与索引并保存。需要旧版任务镜像时，同时选择同步自动整理的任务资料；原始逐轮镜像由“全部已结束对话”独立控制。
3. 开启自动记录，使后续完成、失败或停止的任务过程同步到实际工作区；自动整理在正常 AI 回复中提取摘要和候选知识，不另起模型调用。开启“每轮自动提取分层知识候选”后，具备有效原文依据与适用条件的候选进入对应知识层，并自动附标签。自动记录、自动整理和分层提取各设置组分别保存。
4. 根据需要开启新会话自动补回。关闭不会删除已保存文档，也不会从已经建立的原生会话中撤回先前上下文。

在左侧任务菜单选择 **任务记录与知识**，可查看交接摘要、逐轮 Markdown、相对目录及同步警告，并用 **回填 / 同步本任务已有记录** 导出既有资料。回填受自动记录开关控制，关闭时不会强行写入。旧任务不会在升级时被批量改写；需要时逐个回填。

Windows 任务写 Windows 工作区；WSL、SSH 任务经各自执行通道写该环境中的工作区，需要 Python 3 和目录写权限。远端失败不会回退写入本地同名目录，也不会把已经完成的模型轮次改成失败。可查看提示后修正环境并手动重试。

## 工作区目录与接续

```text
<workspace>/.duo/
  README.md
  tasks/<任务名-稳定短ID>/
    README.md
    handoff.md
    runs/<稳定轮次ID>.md
  conflicts/
```

新建任务需要填写名称。目录用安全处理后的任务名加稳定短标识，避免重名覆盖；首次落盘后改名不反复移动目录。旧纯 ID 目录仅在全部文件仍为未修改的生成内容时安全迁移，并在旧路径保留小型跳转文档；人工编辑或额外文件会阻止迁移并显示提示。

工作区索引链接每个任务。逐轮文件记录初级资料；`handoff.md` 保存有来源的最近进展。任务分叉沿来源追踪原始轮次，同一来源只保留一份逐轮正文，复制任务通过链接引用。相同轮次重复同步不会产生新正文文件。人工改动保留，后续生成内容另存冲突副本，界面提示处理；不要通过删原文件来自动消解冲突。

在输入框旁的模型选择器中选择 AI 引擎与模型。换模型通常沿用原生会话；换引擎时，Duo 自动准备脱敏历史文件和交接提示，在核对接续范围并确认后，下一条消息启动目标引擎。完整历史按文件提供，不每轮重放全部正文。不同引擎的原生会话不能直接互换，历史文件也不包含原来的图片二进制。独立“切换 AI”和“重建 AI 会话”任务菜单按钮已合并；异常恢复仍保留在 **会话与恢复 → 高级会话恢复**。

连续对话由原生会话负责记忆，不会每轮再附加完整历史。新建会话或切换引擎后，开启自动补回时共同执行：

1. 恢复本任务已有摘要与未决事项。
2. 读取同工作区其他任务的交接资料，按原始来源去重，排除已复制到当前任务的轮次。
3. 补入最多五条已确认的平台共识。

各部分均有大小限制，工作区最多补入四个来源片段。它们是可能过时的参考资料，不是本轮已完成的工作，不增加硬件、桌面或网络权限。显式选择的简要恢复范围保持原有范围，避免另加未审阅的资料。保持工作区不变有助于接续，但不能保证任意模型都准确理解全部历史；重要的目标、验证和未决问题应写进交接摘要。

单个工作区副本最多 1 MiB，单次最多 32 MiB、最近 2000 轮。超过限制会提示，完整数据库记录继续保留，已有文件不删除。这是便于阅读的脱敏副本，不是数据库或附件的完整备份。历史中常见路径和凭据会清洗，不能保证识别所有自然语言秘密；在同步工作区到 Git 前仍需检查内容。

## 如何形成正式知识

在知识库预览任务资料，选择 **整理为正式知识**；也可 **新建正式知识**：

1. 选择平台共识、系统知识或项目知识。系统知识填写主题，项目知识填写项目名。
2. 精简正文，填写适用条件、实际依据、未解决问题和标签。
3. 默认为待验证。填写依据及适用条件并明确勾选确认后，才可标为已验证。这是用户确认，不表示 Duo 独立复测。
4. 保存保留来源 ID 与来源 hash；同一来源、同一层级、同一范围不叠加副本。内容相同的重复提升返回已有条目，内容不同会提示编辑已有条目并保留草稿。不同来源描述同一事实仍需人工合并，系统不自动判断语义等价。

自动摘要可提取平台共识、系统知识及项目知识候选，全部以待验证保存，不自动成为已确认共识。正常轮次不另起模型请求；模型未返回有效结构化候选时不会凭空生成知识。

主菜单的三个知识入口支持查看和编辑。**从已有资料提取**只整理已保存的结构化候选，最多最近 1000 轮、32 MiB，不调用模型；没有结构化资料的旧记录，可在选中任务后选择 **AI 整理并提取**。该操作需确认发送最近最多 8 轮成功对话的有限文本摘录，并会消耗模型额度；只根据这些资料提取，不代表处理了完整历史。目前独立 AI 提取支持 Codex、Claude Code 和 Harness，使用独立只读会话，不替换当前任务原生会话。其他引擎仍可从普通回复提取候选，或切换到支持的引擎手动整理。

提取依据层级、范围及规范化正文去重，不做语义合并；不会覆盖已有人工修订、过时或已移除的候选。正式条目支持编辑、过时标记和移除；移除正式条目不会删除原任务记录。修订冲突会拒绝覆盖并保留编辑草稿。

知识的 YAML `tags` 可用于 Obsidian 标签和图谱。在 Duo 的 **关系图谱** 中，文档通过共同标签关联；可筛选标签、缩放、点击文档查看或编辑。图谱最多展示 80 份文档及 20 个标签，超出时可先按层级、项目或标签缩小范围。它展示标签关联，不判断因果关系或结论是否正确。

移除只从当前 Duo 中隐藏并保留已有 Markdown，不传播跨电脑删除；另一台电脑仍可能将旧文件导入为待验证。需要跨电脑保留“已不适用”的信息时，请标记过时并同步，而不是移除条目。

NFS、烧录等正式文档可保留有意义的操作路径；为了跨设备复用，建议使用 `<workspace>`、`<server>`、`<device>` 等模板并写明变量。串口密码、API Key、令牌应保留在设备或受保护配置中，知识只写配置名称/引用。普通 Markdown 与 Git 不适合当作密码库。常见凭据赋值会被拒绝，这不是任意格式秘密的完整检测器。

## Obsidian、迁移与后续消费

Markdown 可直接在 Obsidian 编辑。Duo 每分钟同步，或手动点刷新文件；外部修改正式内容后回到待验证状态，不允许仅改 YAML 自动取得“已验证”。两边同时修改保留冲突。旧 `Duo/tasks/`、候选结论、主题索引和人工笔记继续保留，不自动搬迁或删除。

跨电脑由 Obsidian Git 或其他 Git 客户端负责提交、推送和拉取，Duo 不自动操作 Git。每台电脑设置本机 Vault 路径。任务工作区的 `.duo/` 和 Obsidian 的 `Duo/` 是两个目录：工作区也需要单独同步才能在另一台电脑接续。完整 Duo 数据迁移还包括任务、运行记录和配置；仅同步 Vault 不等于同步原生 CLI 会话或全部运行状态。

目前系统与项目知识通过搜索和带来源引用消费；平台共识可自动恢复到新会话。技能化和 MCP 工具转化尚未实现。后续可以从已验证、适用条件明确、可重复执行的条目手工提炼技能；执行能力仍须单独定义权限、输入和验证，不能仅凭知识正文获得执行权限。
