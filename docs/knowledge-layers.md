# Duo 的任务记忆与知识分层

任务过程用于接续工作，正式知识用于长期复用。自动记录不等于已经验证的知识；引擎原生会话、Duo 数据库和 Markdown 各有用途。

逐步操作和验收见 [知识功能使用与验收](knowledge-acceptance.md)。以下保留实现细节和各版本历史；最新可用流程以该验收清单及文首更新为准。

v0.34.69 补齐普通公开进度中的有效状态增量、同主题 AI 完整合并稿、保留知识身份的根目录迁移。前者随执行快照更新任务文档；主题整理需用户确认后另起模型，原文在采用前不变；迁移需预览后确认，源同步干净且目标无冲突才复制并切根。完整语义限制与历史矩阵适用范围见 [当前架构](knowledge-rebuild-architecture.md#v03469-当前流程与验收边界)。下文早期版本的未完成描述不代表这些新能力仍然缺失。

本次参考了 AHA 的任务工作日志：其 [context_planner.py](https://github.com/ChinaKai/AHA/blob/main/src/aha_cli/services/context_planner.py) 为任务确定稳定的 Markdown 路径，[backend_context_pack.md](https://github.com/ChinaKai/AHA/blob/main/src/aha_cli/prompts/backend_context_pack.md) 要求 AI 持续更新该文件，长期知识另外整理。Duo 采用“一任务一篇可编辑主文档”的组织方式；每轮结束后追加正式来源，v0.34.69 起也接收执行中公开进度的有效状态增量。没有合法增量时保留旧状态，不根据工具活动臆测计划已经完成。

v0.34.67 引入执行期间的独立观察快照：开始时尝试写入，有新事件时最多每 15 秒刷新，正式终态保存后由时间记录接替。v0.34.69 在同一机制中额外折叠有依据的公开状态增量；普通活动快照本身仍不是完成证据。服务重启会排队补写中断状态，磁盘不可访问、退避或人工冲突时保留原文。

## 两层资料

第一层是工作区任务原件；第二层是笔记库内的平台共识、系统知识、项目知识。完整架构与参考资料见 [知识重构方案](knowledge-rebuild-architecture.md)。

| 层级 | 内容 | 主存储与同步 | 使用方式 |
|---|---|---|---|
| 工作区任务资料 | 可编辑任务主文档、按时间追加的进展、失败原因与原始来源 | 任务实际执行环境的 `<workspace>/.duo/tasks/<任务名-短ID>/任务记录.md`；完整记录仍保留在 Duo 数据库 | 任务菜单直接阅读和编辑同一文件；新会话读取有限摘录，续接会话只补文档变化 |
| 平台共识 | 用户明确约定的跨任务习惯和流程 | 笔记根下 `平台共识/`，与 Duo 修订数据双向同步 | 仅用户确认的条目自动供新会话参考 |
| 系统知识 | 概念、原理、方法、学习总结 | 笔记根下 `系统知识/<主题>/` | 搜索、引用及本轮关键词相关检索 |
| 项目知识 | 项目结论、操作资料、问题解决与资料索引 | 笔记根下 `项目知识/<项目>/` | 按项目浏览、搜索及本轮相关检索 |

启用可读布局后，目录与文件使用中文主题名，稳定 ID 在属性中，实际重名才添加短尾。旧配置继续使用原目录，不静默迁移。知识管理以数据库维护正文、修订及来源，并与 Markdown 双向同步；不能把尚未同步的数据库修改视为已经写入 Obsidian。从另一台电脑首次导入的知识为“待验证”，需在当地重新确认。

正式知识改标题或范围后，启用分目录同步时仅在旧文件未被外部修改、目标路径空闲时安全移动；否则沿用原路径并保留内容，不创建重复正文。索引读取实际文件位置。旧版任务主文档仍保持首次导出的文件名。

## 从哪里设置

打开顶部 **知识库 → 目录与整理**：

1. 设置积累根目录，可以选择 Obsidian 内的专用知识文件夹。新配置默认“所选目录就是知识根”；旧配置保留“所选目录下 Duo”的兼容模式，界面显示实际目录。三个分类目录可自定义中文相对路径；保存时创建，不会移动或删除旧原件。
2. 启用 Markdown 同步与索引并保存。新配置默认不导出旧聊天、insight 和主题镜像；需要时显式启用“保留旧资料镜像”。关闭兼容镜像不会删除已有文件。
3. 开启自动记录，使后续完成、失败或停止的任务过程同步到实际工作区；自动整理在正常 AI 回复中提取摘要和候选知识，不另起模型调用。开启“每轮自动提取分层知识候选”后，具备有效原文依据与适用条件的候选进入对应知识层，并自动附标签。自动记录、自动整理和分层提取各设置组分别保存。
4. 根据需要开启新会话自动补回。关闭不会删除已保存文档，也不会从已经建立的原生会话中撤回先前上下文。
5. 可开启定时整理，设置 1～168 小时间隔，默认 24 小时。定时与一键使用同一已有候选提取流程，不额外调用模型；Duo 运行时执行，记录最近成功及失败状态。没有结构化候选的旧聊天仍需显式选择 AI 整理。

在左侧任务菜单选择 **任务记录**，直接打开该任务的主 Markdown。默认阅读正文，选择 **编辑 Markdown** 后可修改目标、计划、备注和既有进展，保存直接写回同一文件。文件被外部编辑器或自动记录更新时，旧版本保存会被拒绝并保留草稿，先核对变化再重新保存。文件的改名稳定规则不变。

主文档尚未生成且自动记录开启时，首次打开会从已有数据库资料回填一次，不调用模型；也可手动同步。回填受自动记录开关控制，关闭时不会强行写入。旧任务不会在升级时被批量改写，原始逐轮文件、交接摘要和旧候选资料保留在辅助区域。

Windows 任务写 Windows 工作区；WSL、SSH 任务经各自执行通道写该环境中的工作区，需要 Python 3 和目录写权限。远端失败不会回退写入本地同名目录，也不会把已经完成的模型轮次改成失败。可查看提示后修正环境并手动重试。

## 工作区目录与接续

```text
<workspace>/.duo/
  README.md
  tasks/<任务名-稳定短ID>/
    任务记录.md
    README.md
    handoff.md
    history/README.md
    history/YYYY-MM.md
    history/YYYY-MM-0001.md
    runs/<稳定轮次ID>.md
  conflicts/
```

新建任务需要填写名称。目录用安全处理后的任务名加稳定短标识，避免重名覆盖；首次落盘后改名不反复移动目录。旧纯 ID 目录仅在全部文件仍为未修改的生成内容时安全迁移，并在旧路径保留小型跳转文档；人工编辑或额外文件会阻止迁移并显示提示。

`任务记录.md` 顶部受管区持续维护目标、目标变更原因、验收标准、计划步骤及状态、进展、决策、证据、阻塞和下一步；下方按时间追加关键变化。对话轮次结束时读取同轮可选 `task_state` 增量，不额外调用模型；失败或停止的轮次也保留已返回的有效增量，其失败或中断状态照常保留，不因此进入仅成功轮次适用的长期知识整理。省略字段保留旧值，显式空数组清空。完成步骤必须带上方回复的逐字依据，这仍是来源报告而非独立复验。没有有效结构化结果时仍展开本轮需求、助手结果和最近执行事件，保留结束时间、状态、失败原因及完整来源入口，不把问候当目标或旧提问当计划。长结果保留开头与结尾，不用截掉最终结论的短摘要替代。

v0.34.65 对旧版只有短摘要/链接的轮次，使用独立详情标记补充一次，不替换原进展块；重复同步不会重复追加。旧“任务目标：你好”只有在整个已知默认模板精确匹配、相关目标/计划/备注未被改动时才纠正。v0.34.66 新增按月分页与持久分批回填：正常主文档/分页目标约 256 KiB，每文件仍限 1 MiB，达到目标后新进展继续写历史页，已有人工内容不截断。主文档提供历史导航和最近进展。超过旧版 2,000 轮的总历史可多次同步，空闲队列有限继续；磁盘失败退避、文件冲突暂停。检查点只在文件成功写入后推进，较早启动而较晚结束的轮次仍有来源跟踪。

关闭长期“自动整理”不影响开启“自动记录”后的第一层状态采集。人工编辑自动区域后，区域自动替换暂停并显示提示；区域外正文保持原字节，时间记录仍按来源追加。每个进展块保留来源标记，重复同步不再次追加。当前执行快照最多每 15 秒落盘，合法公开状态增量随之更新，结束后合并最终增量；不要求每次工具事件产生语义状态。长任务中的显式人工 Markdown 编辑会保留。

迟完成或后导入的旧轮次保留原时间，在发现时追加，不重排已有人工历史。导出检查点不是正文完整性审计：用户事后删除旧正文，不会在每轮同步时全量重扫恢复；安全重放或重置检查点时才回填。

旧 `README.md` 是索引，逐轮文件保留原始副本，`handoff.md` 是内部交接摘要。这些文件继续保留以兼容旧链接，不再作为任务记录的默认打开页。原始生成文件的人工改动仍受冲突副本保护。任务分叉沿来源追踪原始轮次，通过来源链接复用，不删除旧资料。

在输入框旁的模型选择器中选择 AI 引擎与模型。换模型通常沿用原生会话；换引擎时，Duo 自动准备脱敏历史文件和交接提示，在核对接续范围并确认后，下一条消息启动目标引擎。完整历史按文件提供，不每轮重放全部正文。不同引擎的原生会话不能直接互换，历史文件也不包含原来的图片二进制。独立“切换 AI”和“重建 AI 会话”任务菜单按钮已合并；异常恢复仍保留在 **会话与恢复 → 高级会话恢复**。

连续对话由原生会话负责记忆，不会每轮再附加完整历史。v0.34.66 会比较当前任务 Markdown 与该原生会话上次成功接收的脱敏快照：未变则跳过，变更只提供有界变化范围；仅成功后确认读取进度，准备后新增的人工编辑留待下轮。新建会话或切换引擎后，开启自动补回时共同执行：

1. 恢复本任务已有摘要与未决事项。
2. 读取本任务 `任务记录.md` 的有限摘录，涵盖人工目标、计划和备注及近期进展；长文只取开头与结尾，不把全部工作日志自动重发。
3. 读取同工作区其他任务的交接资料，按原始来源去重，排除已复制到当前任务的轮次。
4. 补入最多五条已确认的平台共识。

各部分均有大小限制，工作区最多补入四个来源片段。它们是可能过时的参考资料，不是本轮已完成的工作，不增加硬件、桌面或网络权限。显式选择的简要恢复范围保持原有范围，避免另加未审阅的资料。保持工作区不变有助于接续，但不能保证任意模型都准确理解全部历史；重要的目标、验证和未决问题应写进交接摘要。

单个工作区副本最多 1 MiB，单次写入资料有 32 MiB 安全上限，历史按 64 行批次持续推进，不再只限最近 2000 轮。当前任务状态从已有结构化增量流式折叠，独立于历史导出批次；无效状态不覆盖既有目标。单月最多 9999 页，最多跟踪 2000 个尚未结束的孔位，异常会明确提示并保留原件。这是便于阅读的脱敏副本，不是数据库或附件的完整备份。历史中常见路径和凭据会清洗，不能保证识别所有自然语言秘密；在同步工作区到 Git 前仍需检查内容。

## 如何形成正式知识

在知识库预览任务资料，选择 **整理为正式知识**；也可 **新建正式知识**：

1. 选择平台共识、系统知识或项目知识。系统知识填写主题，项目知识填写项目名。
2. 精简正文，填写适用条件、实际依据、未解决问题和标签。
3. 默认为待验证。填写依据及适用条件并明确勾选确认后，才可标为已验证。这是用户确认，不表示 Duo 独立复测。
4. 保存保留来源 ID 与来源 hash；同一来源、同一层级、同一范围不叠加副本。内容相同的重复提升返回已有条目，内容不同会提示编辑已有条目并保留草稿。同主题修订可明确调用 AI 生成完整合并稿，再人工核对采用；系统不自动判断矛盾结论哪一条正确。

自动摘要可提取平台共识、系统知识及项目知识候选，全部以待验证保存，不自动成为已确认共识。正常轮次不另起模型请求；模型未返回有效结构化候选时不会凭空生成知识。提取提示按可独立阅读的主题组织背景、方法/步骤、原因、结果和限制，同主题沿用标题和范围；仅有零散线索时留在任务资料，不为增加篇幅编造内容。

启用可读布局后，三类知识的默认列表优先展示分类/项目/主题的阅读手册。手册展开已有正文、适用条件、依据与状态，最多 24 条一页，并按字节进一步分页；原始正式笔记仍保存身份和修订，点击原笔记后编辑。手册为只读汇编，不等于重新理解或证实了全部知识。旧分页文件不主动删除；分类首页链接当前页，已外部编辑的文件遇到冲突仍保留。知识列表显示摘要和项目；打开长文可按章节、文首和文末跳转，路径与来源在折叠详情中。

总菜单只保留 **知识库** 一个入口，在同一窗口内选择平台共识、系统知识或项目知识，并可查看、编辑和浏览关系图谱。旧任务镜像、候选和主题索引留在历史资料，不作为重复的总菜单入口。

**一键整理已有候选**只整理已保存的结构化候选，最多最近 1000 轮、32 MiB，不调用模型；没有结构化资料的旧记录，可在选中任务后选择 **用 AI 整理本任务**。v0.34.66 会先预览待整理轮数，明确确认后按时间处理尚未整理的终态聊天，每批最多 16 轮，包含失败和停止；附当前任务 Markdown 与相关旧主题的有界摘录。有效结果保存成功后推进本批来源，失败或遗漏明确候选数组时留待重试；再次点击继续下一批，不代表一次理解全部历史。此操作会消耗当前模型额度，独立支持 Codex、Claude Code 和 Harness，使用只读会话，不替换原生聊天身份。其他引擎仍可随普通回复提供候选，或切换支持的引擎手动整理。

提取依据层级、范围及规范化正文去重，不做语义合并。同层级、同范围、同标题的新内容作为原条目的待合并修订，不直接改原正文；可预览、采用或忽略。采用后退回待验证，保留修订来源；忽略后重复提取不会重建该修订。采用前检查原正文基线及版本，已有编辑不被覆盖。条目可编辑、标过时或移除，移除不会删除原任务记录。

知识的 YAML `tags` 可用于 Obsidian 标签和图谱。在 Duo 的 **关系图谱** 中，文档通过共同标签关联；可筛选标签、缩放、点击文档查看或编辑。图谱最多展示 80 份文档及 20 个标签，超出时可先按层级、项目或标签缩小范围。它展示标签关联，不判断因果关系或结论是否正确。

移除只从当前 Duo 中隐藏并保留已有 Markdown，不传播跨电脑删除；另一台电脑仍可能将旧文件导入为待验证。需要跨电脑保留“已不适用”的信息时，请标记过时并同步，而不是移除条目。

NFS、烧录等正式文档可保留有意义的操作路径；为了跨设备复用，建议使用 `<workspace>`、`<server>`、`<device>` 等模板并写明变量。串口密码、API Key、令牌应保留在设备或受保护配置中，知识只写配置名称/引用。普通 Markdown 与 Git 不适合当作密码库。常见凭据赋值会被拒绝，这不是任意格式秘密的完整检测器。

## Obsidian、迁移与后续消费

Markdown 可直接在 Obsidian 编辑。Duo 每分钟同步，或手动点刷新文件；外部修改正式内容后回到待验证状态，不允许仅改 YAML 自动取得“已验证”。两边同时修改保留冲突。旧 `Duo/tasks/`、候选结论、主题索引和人工笔记继续保留，不自动搬迁或删除。

v0.34.65 离线脚本默认 `readable`：每任务一份档案，轮次按时间写入分页月日志，知识按项目/主题合编阅读手册。实际输出 `<知识根>/知识重整-20261030/`，共 19 个任务、808 个轮次、71 份手册，另附一份选读 7 份原始回复的 375 导读。原文、依据、适用条件、来源与哈希可追溯，结论冲突和资料缺口不会被隐藏。它是**独立阅读整理视图**，不创建正式 `curated` 身份，不改现有数据库或笔记设置，也不代表重做历史实验。

旧 `<知识根>/知识整理-20261030/` 属于 v0.34.64 的 `source-notes` 逐条模式，会重建条目 ID 和来源 ID。不要将已有数据库直接切到任一整理目录并期待无重复迁移：正式迁移仍需保留身份、来源和修订历史，提供已有条目的路径接管及新增、修订、重复、冲突预览。整理脚本的用途和分版本实际报告见 [知识重构方案](knowledge-rebuild-architecture.md#本地旧资料的非破坏整理)。

跨电脑由 Obsidian Git 或其他 Git 客户端负责提交、推送和拉取，Duo 不自动操作 Git。每台电脑设置本机 Vault 路径。任务工作区的 `.duo/` 和 Obsidian 笔记根是两个目录；只有兼容模式在笔记根下额外使用 `Duo/`。工作区也需要单独同步才能在另一台电脑接续。完整 Duo 数据迁移还包括任务、运行记录和配置；仅同步 Vault 不等于同步原生 CLI 会话或全部运行状态。

系统与项目知识可搜索和带来源引用；开启自动补回时，每轮还按问题、标题、范围和标签匹配最多 4 篇有界摘录，过时知识不注入，待核对候选只作为调查线索。平台共识仍只自动恢复已确认条目。当前为关键词相关检索，不是向量或 GraphRAG。技能化和 MCP 工具转化尚未实现；执行能力仍须单独定义权限、输入和验证。

v0.34.66 可在“任务记录 → 知识项目范围”显式选择稳定项目，支持名称和别名，优先于工作区/标题猜测；分叉继承，历史执行保留提交时归属。检索忽略已经注入的知识块，避免块内项目名成为新的“用户明确提及”。脱敏工作区 ZIP 包含项目归属，导入只追加并协调名称/别名，冲突保留本机配置并报告，不静默更改旧项目。
