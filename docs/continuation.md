# 跨引擎任务接续

Duo 将任务记录与原生引擎会话分开。v0.24.1 起，“切换 AI”保留同一个任务 ID、聊天记录、知识、待办和未发送草稿，修改下一轮执行的引擎、账号/API 引用和模型。Codex、Claude Code 和 DeepSeek Harness 的原生 session ID 不能互相复用。

## 用户流程

1. 等当前运行结束，或先停止并取消排队。点击标题栏或任务菜单的“切换 AI”。
2. 选择引擎、账号/API 配置、模型和权限。模型列表读取所选配置，不发测试提示词；也可填写模型 ID，列表存在不等于调用可用。
3. 默认沿用工作目录，默认选择“完整历史文本 + 接续摘要”。展开执行位置可更换环境和目录；也可明确选择仅笔记与共识。阅读摘要，必要时打开完整脱敏文本。
4. 确认切换只保存配置，不立即调用模型。回到原任务发送下一条要求后才开始执行。
5. 同一引擎、环境、目录和账号只换模型时继续原生会话；换引擎、账号或执行位置时建立新会话。Harness 权限改变也需新会话。失败会保留记录并显示错误，不静默退回另一账号。

“会话信息”和“复制链接”从顶部移到左侧任务的操作菜单，外部项目指令及会话恢复诊断仍可查看。

## 配置账号/API

在“设置 → AI 引擎 → 添加或更新账号/API 引用”添加目标环境可访问的原生配置目录。Codex 使用 `CODEX_HOME`，Claude 使用 `CLAUDE_CONFIG_DIR`，Harness 使用 `DSH_HOME`。API 地址和密钥在相应引擎的配置里管理，Duo 不复制凭据，也不把任意 OpenAI 风格 API 自动转换成所有引擎的协议。

v0.31.0 起默认跟随环境账号；在账号管理中「切换环境账号」后，已有跟随任务与排队消息从下一轮执行时生效。「仅此任务使用」可固定任务账号。详见 [环境账号与任务](environment-accounts.md)。外部修改同一目录中的登录或 provider 仍会影响该目录，建议不同账号/API 使用不同目录。v0.24.2 起，没有账号快照的旧任务可在“切换 AI”中选择原来的账号/API 配置，保持引擎、执行环境、目录和原权限不变，勾选“我确认所选配置就是此任务原来的账号 / API，保留原会话继续”后确认。此操作仅补齐绑定，保留原生 Session，不重建或回放历史；打开或取消窗口不修改任务。账号归属依据用户明确确认，Duo 无法从旧记录自动证明；不能确认或已换账号时保持不勾选，继续通过新会话接续。

## 历史如何交接

- 内联摘要最多约 13,000 字符，优先最近共识、前提、未解决事项、笔记和最后几轮。它不声称覆盖全部历史，也不是额外模型总结。
- 完整所选文本包含本任务全部已结束的聊天轮次（包括失败、停止）、追加引导、已有工具记录、任务笔记及结构化记忆。连续累积的流式文本合并为最终片段，不重复附加相同正文。每轮保留原引擎标记。
- 完整文本作为可读取的 Markdown 文件传入执行环境；较早内容由目标引擎按需读取。不是把全部文本一次性灌入模型上下文，也不能保证模型已经读取每一条。每轮重建临时文件并在结束后清理，提示词提供当轮有效路径；不会往用户项目写历史文件。
- 原生 session、凭据文件、图片等二进制附件不转移；需要原图时重新附加。历史工具日志是资料，不是待执行命令。内容做路径和常见凭据脱敏，但不能保证任意正文里都没有敏感信息，提交前仍可查看全文。
- 单次所选历史上限 64 MiB，超过时明确拒绝，不静默裁掉早期记录。历史资料只在预览、手动切换或执行前检测到账户变化时构建，不加入聊天轮询负载。数据库中的原始记录不删除。
- “新建会话”明确清除接续文件绑定，之后只按自动恢复知识设置补回少量资料；它与“切换 AI”用途不同。

## 一致性与接口

任务绑定记录账号模式及原生会话的账号归属；每个已提交轮次固定引擎、模型和账号模式。单独指定的 profile 固定，跟随环境的 profile 在执行前解析；账号不变时原生 session 由前一轮传递，账号改变时创建新会话并保存历史。切换在同一数据库事务中保存配置、历史快照和旧会话信息。重复提交可重试；预览、任务绑定或所选账号配置过期时拒绝切换。切换失败不留下半个新任务，也不会改变全局默认账号。

接口为：

- `GET /api/tasks/{id}/continuation/preview?mode=full`：本地摘要、全文字节数和指纹，不调用模型。
- `GET /api/tasks/{id}/continuation/archive?mode=full`：需要登录的纯文本全文预览。
- 新版“仅任务笔记与共识”使用 `mode=notes`，保留尚未独立验证的笔记并明确标注。兼容范围 `summary` 仍只包含标为已验证的笔记，`recent` 仍使用已验证笔记和最近 8 轮成功对话。
- `POST /api/tasks/{id}/handoff`：要求 `confirm`、预览指纹、任务绑定版本、明确的目标配置和权限；原子更新原任务，不提交模型轮次。旧版没有指纹的转接请求会被拒绝。旧任务明确确认原配置时可传 `preserve_legacy_session=true` 与匹配的 `expected_legacy_session`；`mode_id=__current__` 保留原权限快照（含早期未显式保存的默认权限）。引擎、执行环境、目录、权限发生改变时拒绝保留旧会话。
- 模型目录支持明确 `profile_id`，或者用 `task_id` 读取任务绑定；任务内模型测试还核对绑定版本，仍需要用户单独确认付费测试。

回归使用合成记录、临时配置目录和 fake runner，覆盖同任务跨引擎、同账号换模型、不同账号新会话、长历史、重复与过期提交、事务回滚、排队隔离、账号模型目录、草稿和窄屏。真实模型接续质量、具体 provider 兼容性和 WSL/SSH 远端读档效果需另行授权实测；本轮没有发送真实模型请求。
