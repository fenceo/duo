# 全局知识库与知识文件目录

0.22.0 新增默认开启的[对话自动积累](automatic-knowledge.md)：成功对话的要求与最终回复会自动保存到本机任务知识。若也要写入 Vault，另勾选“同步自动积累的知识”；这个选项默认关闭，不改变既有人工结论的同步范围。

Duo 的知识库可以搜索当前电脑中所有任务的已结束记录和知识结论，也可以索引 Obsidian Vault 中的 Markdown。新建任务、切换任务后，都可点击“引用历史 / 知识”，查询并将选中的内容加入输入框，检查后再发送。检索和文件同步不会调用模型。

## 三个入口的用途

- 顶部“本任务知识”：查看、搜索、编辑、验证、标记过时或删除当前任务的知识。正文默认收起，点击标题展开；可按来源与验证状态筛选。自动记录也在这里；“手动整理”是可选的模型整理操作。
- 左侧“知识库”：搜索所有任务的历史、知识与已索引的 Markdown，并引用到输入框。“管理本任务知识”可返回当前任务的管理面板。
- “设置 → 知识库”：统一配置自动积累、知识文件根目录和同步范围。全局知识库中的“知识库设置”也能直达这里。

“本任务知识”与全局检索使用同一份知识条目，无需重复保存。任务、对话和知识仍共用运行数据目录中的数据库；设置页会显示当前目录。知识文件目录是可同步、编辑和共享的 Markdown 副本；若要迁移整个运行数据库，请使用“设置 → 数据与存储”。

## 日常查找和复用

1. 从左侧“知识库”或输入框底部“引用”进入。默认浏览知识条目，避免把同一轮自动记录与原始对话混在一起；需要完整旧记录时切换“原始对话”。
2. 输入关键词，按任务和来源缩小范围。来源可选对话自动记录、手工保存与整理、知识文件目录。自动记录仍是待验证的历史回复，并不代表已经整理、核实或自动合并。
3. 点击条目标题预览正文、来源和验证状态。桌面并排显示列表与预览，手机可以返回结果列表。超长资料明确提示截断。
4. 点击“引用”，资料会带着来源和验证状态加入当前草稿，检查后再发送。打开知识库和预览不会启动模型。资料在选择后发生修改，会拒绝过期引用并要求刷新。
5. 要修改结论，可从预览打开来源任务，再在“本任务知识”维护。编辑时保留打开条目时的版本号；其他窗口同时修改会提示冲突并保留草稿，不用新版本号静默覆盖。

知识库顶部会读取实际设置，分别显示自动记录、新会话补回和文件同步状态。此处只展示状态，不覆盖设置页尚未保存的输入。展开“AI 什么时候会用到这些内容？”可查看消费范围；浏览全局知识库不等于把所有资料自动交给 AI。

## 第一次配置

1. 创建一个普通文件夹，也可使用现有 Obsidian Vault。文件夹必须已经存在，并且能够被运行 Duo 服务的电脑访问。
2. 打开“设置 → 知识库 → 知识文件目录与同步”。
3. 填入根目录的绝对路径，例如 `E:\Notes\MyVault`。这是运行 Duo 服务的电脑上的路径；手机访问网页时也填写服务电脑的路径。所有任务共用这个设置，保存后会显示实际文件目录 `E:\Notes\MyVault\Duo`。
4. 勾选“启用 Markdown 同步与索引”。若需将对话中自动积累的知识也保存到文件，勾选“同步自动积累的知识”；如需导出原始问题、回复及失败原因，再勾选“同时保存全部任务的已结束对话记录”。这两个额外范围默认关闭，彼此独立。
5. 点击“保存知识库路径与同步设置”后立即同步；之后每分钟同步一次。Git 拉取或编辑 Markdown 后也可点击“立即同步 / 重建索引”。

更换根目录会在新目录同步当前选定范围内的资料，旧目录文件保留。Duo 不自动搬移旧目录的文件，旧目录中的独立笔记需要自行复制到新目录的 `Duo/`。启用同步时，无效的新目录会被拒绝，原设置保持不变。关闭同步或缩小导出范围也不会删除已写出的文件。

Duo 只管理 Vault 下的 `Duo/` 子目录，不修改 `.obsidian/` 或 Vault 的其他笔记。要让现有笔记参与检索，可以将选定的 Markdown 放入 `Duo/`，支持子目录。普通笔记不要求 Duo 属性。

```text
MyVault/
  .obsidian/                 # Obsidian 自己的配置
  Duo/
    knowledge/<条目ID>.md    # 一条结论一个文件，可编辑
    run/<执行ID>.md          # 一次执行一个文件，保留问题、回复、错误
    项目说明.md              # 用户选定的其他资料
```

文件使用 UTF-8 和 YAML 属性，ID 文件名保持稳定，修改标题不会改变同步路径。属性包括 `duo_id`、`duo_kind`、`duo_task`、`duo_task_title`、`duo_run`、`title`、`status`、`duo_revision` 和 `duo_updated`。状态 `observed`、`verified`、`stale` 分别表示待验证、已验证、已过时。不要修改 `duo_id`、`duo_kind` 或 `duo_task`；它们用于关联来源。

## 两台电脑通过 Git 共用

Git 仓库保存 Markdown；每台电脑的 Duo SQLite 数据库、会话、执行环境、账号和本地路径各自独立，不通过 Git 同步。

1. 将 Vault 放在自己的 Git 仓库，优先使用私有仓库。可使用 Obsidian Git 插件、Git 图形客户端或命令行。
2. 电脑 A 在 Duo 同步完成后检查变更，提交并推送 `Duo/`。
3. 电脑 B 克隆同一仓库；之后每次先拉取最新版本，再在 Duo 配置 B 的 Vault 路径并刷新索引。
4. B 不需要拥有 A 的原始任务数据库，就能在新任务中查询和引用同步过来的记录。索引不会创建可执行任务，也不会复用 A 的原生模型会话。
5. 结束编辑后提交并推送；换电脑时先拉取再编辑，减少并行修改冲突。

Duo 不运行 Git 命令、不保存 Git 凭据、不替你自动提交或推送。可以在 Obsidian Git 中配置这些操作；不要同时用多个工具自动合并同一批文件。Git 冲突需要在 Git 客户端或编辑器中解决，然后刷新 Duo。

## 编辑、冲突和删除

- 在 Duo 修改已有结论，若对应 Markdown 没有同时变化，下次同步更新 Markdown，并保留 `tags` 等自定义属性。
- 在 Obsidian 修改该结论的正文、标题或状态，若本机结论自上次同步后没变化，下次同步导入修改并增加本地 revision。
- 如果两端都发生变化且内容不同，Duo 保留两端内容并列出冲突文件。可分别在 Duo 和 Obsidian 中编辑成相同的正文、标题、状态，再同步；不要直接删除一端来绕过冲突。
- Git 拉取的结论如果在这台电脑没有对应任务，作为 Vault 文档索引，可直接引用；不会自动伪造任务或来源记录。
- 执行记录是原始证据。修改其 Markdown 只改变 Vault 的副本，不会覆盖原始 runs/events。
- 初次连接已有同 ID 文档而没有共同同步基线时，内容不同会提示手工合并，不按文件时间决定谁覆盖谁。
- 本地结论或任务的删除不联动删除 Vault 档案。删除 Vault 文件并刷新后，该副本退出索引；已跟踪的文件不会自动重建。其本地原始记录仍可检索。需要彻底移除时分别处理两端，并由 Git 保存可恢复历史。
- 不建议重命名自动导出的 ID 文件。改名会作为独立资料索引，原同步路径被视为移除。
- 含常见密钥的内容导出时脱敏；如果脱敏副本又被外部编辑，Duo 会要求手工合并，防止它覆盖本地完整原文。脱敏并不保证识别所有秘密，推送前必须审阅要共享的 Markdown。

## 检索与引用范围

支持中文短词、报错码和空格分隔的多个关键词，可按任务、资料类型和来源筛选。当前是本地关键词检索，不使用向量模型；同义改写可能需要换关键词。每页最多 60 条，可点击“加载更多”；筛选在分页前执行，已验证知识优先。已过时资料默认排除，可显式勾选查看。本任务面板仍只加载最近 500 条，并显示这个边界；更早内容使用全局知识库查找。

引用附带来源 ID 或 Vault 相对路径、原任务名、状态和内容版本指纹。正文最多引用 6000 字符，超长会明确标记截断；引用会进入可编辑的输入框，不会直接启动任务。选择后资料版本变化时会要求重新检索。切换任务或重新登录时，迟到的引用请求不会写入另一个任务。

资料只是历史证据，不构成执行权限，不能把历史回复的“已完成”当成当前电脑已完成，也不能把成功的模型输出自动升级为已验证知识。

## 文件边界与限制

索引为可重建缓存。只读取 `Duo/` 内非隐藏的普通 Markdown，跳过符号链接和目录联接，不导入数据库、登录凭据、附件或工具日志。单文件最多 2 MiB，一次扫描最多 10000 个文件 / 128 MiB；超过限制会提示，不会假装完整导入。导出的超大执行记录会保留在本地并报告未导出。

存在 Git 冲突标记或无效 YAML 的文件暂不入索引；刷新时移除其旧缓存。启用 Vault 只表示写入本地选定目录，并不代表已经 Git 推送或另一台电脑已拉取。
